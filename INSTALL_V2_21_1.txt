V2.21.1 – controlled projector/camera full-frame capture
========================================================

This is a delta on top of V2.21.
Copy the files into the repository root and restart Skjutbana before using the
new automation argument.

Purpose
-------
V2.21 proved that the old 100 candidate packs are patch-only and cannot be
used for an honest full-frame AI_DIRECT benchmark.  V2.21.1 adds a per-run
iteration override to the existing automation path so a small 10/30-shot
full-frame capture can be collected before spending time/disk on 100 shots.

Smoke run (recommended first)
-----------------------------
1. Start the main Skjutbana application normally with projector and camera.
2. In another terminal, from repo root:

   python3 -m automation.autostart_ai_training white --iterations 10

3. Audit all capture sessions:

   python3 -m automation.physical_pack_v221_inspect \
     --root content/ai/candidate_shadow_v216

Expected after the smoke run:
- Packs increase by 10.
- Full recent PRE shots increase by 10 (or very close; a missing camera frame
  must be reported rather than invented).
- Full POST shots increase by 10.
- Direct-ready full shots increase by 10.

4. If direct-ready full shots are present, run:

   python3 -m automation.direct_proposal_v221_benchmark \
     --root content/ai/candidate_shadow_v216

The benchmark automatically skips the historical patch-only packs and uses
only packs with honest recent PRE + POST full frames.

Next collection after smoke succeeds
------------------------------------
Collect three 30-shot camera-domain sessions:

   python3 -m automation.autostart_ai_training white --iterations 30
   python3 -m automation.autostart_ai_training checker_anim --iterations 30
   python3 -m automation.autostart_ai_training bubbles --iterations 30

Run the audit and direct benchmark again after each session or after all three.
Do not start overnight training yet.  The immediate target is candidate oracle
recall from CURRENT vs AI_DIRECT vs their union.
